## 2. Educational simulator design (Days 3–14)

### 2.1 Boundary
- `internal/raft`: pure protocol. `Node.Step(msg) / Node.Tick()` → returns `(outMessages, persistRequests, applyEntries)`. No goroutines, no time, no I/O, no randomness except a seeded source passed in.
- `internal/simulation`: virtual clock, message queue, fault scheduler, trace recorder. Owns all nondeterminism through one seeded `*rand.Rand`.

### 2.2 Event loop
```
loop until stop condition or MaxSteps:
    choose next event using rng: deliver(queue[i]) | drop(queue[i]) | duplicate(queue[i])
                                 | tick(node) | crash(node) | restart(node) | partition(set) | heal
    apply event to the target node; collect outputs; enqueue messages; record trace line
    check invariants after every event (§4)
```
- Determinism requirement: same seed + same code → byte-identical trace. Test `TestDeterminism` runs each seed twice and compares trace hashes.
- No `time.Sleep`, no wall clock, no map iteration order in decisions (sort keys).

### 2.3 Persistence in the simulator (stage-appropriate)
Days 12–13 define a **simple** persistence model: on crash, a node keeps `(term, votedFor, log)` that it "persisted" through an explicit persist output, and loses everything else. No fakefs here. Documented in `docs/results.md` as an assumption of the simulator.

### 2.4 Mutation testing (to prove tests can fail)
Each core rule has a build-tagged or flag-controlled mutant. The suite must **fail** for each:
| Mutant | Breaks | Must be caught by |
|---|---|---|
| `vote_not_persisted` | S1 | SIM-E05 |
| `no_log_freshness_check` | S4 | SIM-E03 |
| `no_prev_log_check` | S3 | SIM-R05 |
| `commit_old_term` | R-COMMIT | SIM-C02 |
| `apply_uncommitted` | S5 | SIM-R04 |

Gate evidence includes the failing output for each mutant.

## 4. Invariant checkers (run after every simulator event)

- **ElectionSafety:** map term → leader; second distinct leader in a term = violation.
- **LogMatching:** for every pair of nodes and every index where both have the same term, the prefixes are equal.
- **LeaderCompleteness:** a global "committed set" (index → entry, recorded when any leader commits); every node that becomes leader must contain all of it.
- **StateMachineSafety:** global map index → applied entry; any node applying a different entry at that index = violation.
- **CommitMonotonic:** no node's `commitIndex` decreases within one boot.

A violation stops the run and dumps the trace, seed, and minimal state.

## 5. Database-level simulation (L3) and fakefs

- Runs three real `internal/server` instances (etcd/raft + adapter + storage + state machine) inside one process with:
  - `fakefs` (`docs/storage.md` §10) per node,
  - simulated network (same queue/fault model as §2),
  - virtual time driving `node.Tick()`,
  - a **simulator-owned audit log**: every call to `execute(op)` (not dedup hits) is appended to an audit stream that lives outside the nodes and survives node crashes. Execution counts are taken from this log.
- Failpoints (named hooks) in storage and server code, e.g. `fp.AfterWALWriteBeforeSync`, `fp.AfterMetaSlotA`, `fp.AfterMetaPublished`, `fp.AfterCleanup`, `fp.AfterApplyBeforeRespond`, `fp.AfterSnapshotWrite`.
- **Barriers** (explicit, deterministic):
  - `LeaderElected()`: a node reports leader and has committed its current-term entry.
  - `Quiescent{NetworkEmpty, HeartbeatsAfterCommit: n, AllApplied: idx, NoCandidates, MaxTicks}`: fails the test (never skips) if not reached within MaxTicks.
- Rule: **leader assertions** may be made immediately after a client response; **follower assertions** only after a `Quiescent` barrier.

### 6.4 The snapshot regression test (full specification)

`TestSnapshotRecovery_NoGenerationFallback` (L3, seed 42). History:

| Idx | Entry | Expected |
|---|---|---|
| 1 | no-op (term 1, leader A) | — |
| 2 | Register P | client_id 2 |
| 3 | Register Q | client_id 3 |
| 4 | P seq1 PUT(x,10) | OK |
| 5 | P seq2 CAS(x,10,20), **response dropped** | swapped=true, x=20 |
| 6 | Q seq1 PUT(x,10) | OK, x=10 |
| 7 | Q seq2 PUT(w,1) | OK, w=1 |

Steps: barrier `AllApplied(7)` → all nodes snapshot at **6** with failpoint `AfterMetaPublished` (crash #1) → assert old artifacts still on disk and both slots = new gen → restart with failpoint `AfterCleanup` (crash #2) → assert old artifacts gone → restart → per node: `LoadedGen` = new gen, `SnapshotIndex = 6`, `FirstReplayedIndex = 7`, `AppliedAfterRecovery ≥ 7` (≥ because durable HardState.Commit is a lower bound; exact value recorded in trace) → `LeaderElected` (no-op at 8) → P retries seq2 → **leader-only** assertions: response swapped=true, leader commit ≥ 9, leader x=10 → `Quiescent` barrier → all nodes: commit=9, applied=9, x=10, w=1, sessions {2: seq2 CAS swapped, 3: seq2 OK}, audit count(2,2)=1, equal state hashes → Porcupine OK with P's first CAS ambiguous → slot corruption sub-cases (STO-M04..M06) on node C while A, B continue.

Bugs it detects: snapshot omits session table (x becomes 20, audit = 2); recovery replays from oldest segment on disk instead of floor (`FirstReplayedIndex ≠ 7`, masked by dedup otherwise); cleanup before both slots published (STO-M06 reachable).

## 7. Linearizability checking (L5)

- Library: Porcupine (`github.com/anishathalye/porcupine`, version to pin).
- Model: per-key register with PUT, DELETE, CAS, GET; partitioned by key.
- History recording: client harness records invocation and response times from the **simulator clock** (L3) or a monotonic clock (L4).
- **Ambiguous operations** (TIMEOUT, lost response): recorded with an unknown outcome. Exact Porcupine mechanism for unknown results to be **verified** against the pinned version (expected approach: response time = end of history and output accepting any result).
- Failure output: Porcupine visualization saved with the seed.
- Limitation: passing finite histories is evidence, not proof.

## 8. Evidence requirements for any claim

A claim "X holds" in any review must cite:
1. Test ID(s) and file path.
2. Exact command, e.g. `go test ./tests/sim -run TestElectionSafety -seeds 1-1000 -count=1`.
3. Go version, OS, pinned dependency versions.
4. Raw output (pass counts, seeds, durations), committed under `docs/results/`.
5. For safety claims: the mutant(s) that make it fail.

If execution was not possible, the review says so explicitly. Nothing is reported as passing that was not run.
